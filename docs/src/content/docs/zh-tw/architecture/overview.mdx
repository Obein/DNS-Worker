DNS Worker 採用統一業務核心與雙執行時引擎架構，支援在 Cloudflare Workers 邊緣網路以 Serverless 模式執行，或在獨立伺服器/VPS 以 Serverfull 守護程序模式執行。系統覆蓋 DNS 全協議棧解析、分塊布隆規則過濾、後量子端到端加密（PQC E2EE）以及前端本地優先（Local-First OPFS）資料分析。

## 系統分層與元件設計

DNS Worker 在邏輯架構上解構為五大垂直層級：

### 1. 多協議網路接入層

負責將異構傳輸協議的輸入報文統一標準化為二進位制 DNS 報文（DNS Message）：

- **UDP 53 接入元件 (`src/serverfull/udp.ts`)**：基於 Node.js 原生 `dgram` 套接字繫結 `53` 埠，採用無鎖二進位制切片直接讀取報文頭部，內建滑動視窗速率限制防禦 DNS 反彈放大攻擊。
- **DoT 853 接入元件 (`src/serverfull/dot.ts`)**：基於原生 `tls` 模組監聽 `853` 埠，處理 RFC 7858 兩位元組長度字首分包，並在 TLS 握手階段動態提取 SNI 路由接入點（`<profileKey>.dns.example.com`），實現 Android 原生私密 DNS 接入多租戶分流。
- **DoH / HTTP 接入元件 (`src/api/doh.ts`, `src/serverfull/http.ts`)**：實現標準 RFC 8484 規範（支援 GET Base64URL 與 POST 二進位制 Payload），支援 HTTP/2 與 HTTP/3，並在響應中動態注入包含公鑰標識與引數的 RFC 9460 HTTPS / SVCB 資源記錄以支援 ECH（加密客戶端 Hello）。

### 2. 規則引擎與布隆分發層

負責對解析請求進行合規審計與攔截判定：

- **三級級聯過濾判定鏈**：
  1. **白名單優先繞過**：匹配自定義白名單域名，命中直接放行。
  2. **精確與萬用字元規則匹配**：基於倒排域名樹和 Hash 表實現對自定義規則的亞微秒匹配。
  3. **分塊分層布隆過濾器**：針對收錄數十萬至數百萬域名的開源規則集，通過 MurmurHash3 演算法將其壓縮為多組輕量級分塊點陣圖（每塊 256KB~1MB），保持 0 假陰性且假陽性低於 0.1%，記憶體開銷比傳統樹結構降低 90% 以上。
- **規則同步與編譯管道 (`src/utils/sync/`)**：定時拉取外部訂閱，執行流式過濾、域名清洗、Punycode 轉換與去重，編譯完成後分塊持久化至資料庫。

### 3. 核心解析與上游排程層

負責在域名合規放行後，排程遞迴解析器獲取權威結果：

- **解析管線排程器 (`src/pipeline/index.ts`)**：
  - **響應快取 (`src/pipeline/cache.ts`)**：維護帶 TTL 的自適應快取，對攔截域名直接合成攔截響應並設定短 TTL，減少冗餘請求。
  - **ECS (EDNS Client Subnet) 注入與脫敏 (`src/utils/dns/injectEcs.ts`)**：截斷客戶端 IP 為 `/24` (IPv4) 或 `/48` (IPv6) 網段資訊注入請求，使 CDN 獲得就近排程能力的同時隔離客戶端精確 IP。
- **多協議併發上游排程**：同時管理 DoQ (`quic://`)、DoH+ECH (`https://`)、DoT (`tls://`) 與傳統 UDP/TCP 上游，支援併發競速（Race）與故障轉移熔斷機制。

### 4. 資料持久化與儲存抽象層

負責提供跨平臺統一的資料存取介面與敏感資料保護：

- **統一資料庫驅動抽象**：為 Cloudflare D1、Turso / libSQL（通過 Hrana v2 HTTP Pipeline 批次執行與短讀快取）以及本地 `node:sqlite` 提供一致的 `D1Database` 契約。
- **雙層系統信封加密 (`src/utils/envelope.ts`)**：通過系統主金鑰 `KEK_v1`（相容 `KEK_v0`），對儲存於資料表中的敏感憑證（TOTP 金鑰、API Token、Profile Key）在入庫前執行 AES-256-GCM 信封加密。
- **非同步日誌緩衝聚合器 (`src/pipeline/logBatcher.ts`)**：DNS 解析完成後，日誌任務直接投遞至記憶體佇列，藉助 Cloudflare Workers 的 `ctx.waitUntil()` 或 Node.js 非同步事件迴圈在後臺微批次合併寫入，不佔用關鍵響應鏈路時間。

### 5. 前端互動與本地優先層

負責將分析計算與日誌解密下沉至客戶端：

- **WASM SQLite + OPFS 本地儲存**：前端在獨立的 Web Worker 執行緒中執行官方 WebAssembly SQLite 資料庫，並持久化到 Origin Private File System (OPFS)。
- **本地即時多維分析**：日誌全文檢索、客戶端分佈過濾與地理國家流向統計均在本地 Worker 執行緒毫秒級執行，不消耗雲端資料庫讀配額。
- **客戶端後量子零知識解密 (`web/src/crypto/pqc.ts`)**：啟用 E2EE 後，服務端僅儲存密文；客戶端通過 WebAuthn 硬體通行金鑰（Passkey）在瀏覽器記憶體中解開主私鑰，本地還原明文日誌。

## 資料流與互動機制

### 1. 端到端 DNS 查詢與解析流

```mermaid
sequenceDiagram
    autonumber
    participant Client as 客户端
    participant Ingress as 接入层 (UDP/DoT/DoH)
    participant Pipeline as 业务管线
    participant Filter as 过滤引擎 (Bloom/Rules)
    participant Upstream as 递归上游 (DoQ/DoH/DoT)
    participant Batcher as 异步日志缓冲器

    Client->>Ingress: 发送 DNS 查询报文
    Ingress->>Pipeline: 标准化二进制报文
    Pipeline->>Pipeline: 检索本地响应缓存 (TTL Cache)
    alt 缓存命中 (Cache Hit)
        Pipeline-->>Ingress: 返回已缓存 DNS Answer
        Ingress-->>Client: 交付响应结果
    else 缓存未命中 (Cache Miss)
        Pipeline->>Filter: 提交域名合规判定
        Filter->>Filter: 校验白名单、黑名单与分块布隆过滤器
        alt 判定拦截 (Blocked)
            Filter-->>Pipeline: 阻断判定 (返回 0.0.0.0 / CNAME)
        else 判定放行 (Allowed)
            Filter-->>Pipeline: 放行判定
            Pipeline->>Pipeline: 注入脱敏客户端子网 (ECS)
            Pipeline->>Upstream: 并发向上游递归解析
            Upstream-->>Pipeline: 返回权威解析记录
            Pipeline->>Pipeline: 更新本地响应缓存
        end
        Pipeline-->>Ingress: 交付最终解析报文
        Ingress-->>Client: 返回 DNS 响应给客户端
        Pipeline-)Batcher: [异步解耦] 投递日志事件 (ctx.waitUntil)
        Batcher->>Batcher: 微批次聚合与加密写入数据库
    end
```

### 3. 審計日誌採集與後量子零知識 E2EE 加密流

```mermaid
sequenceDiagram
    autonumber
    actor Admin as 管理员/用户设备
    participant WebUI as 浏览器前端 (Local-First)
    participant Passkey as 硬件通行密钥 (WebAuthn)
    participant Server as 服务端 API / Worker
    participant DEK as 每小时 DEK 管理器
    participant DB as 数据库持久层

    Note over Server,DB: 服务端加密采集阶段 (入库时不持有私钥)
    Server->>DEK: 申请当前小时有效数据加密密钥 (DEK)
    alt DEK 已过期或不存在
        DEK->>DEK: 生成 256 位随机对称密钥 DEK
        DEK->>Server: 读取用户公开的 ML-KEM-768 公钥
        DEK->>DEK: 执行 KEM 封装: encapsulate(PubKey) -> (SharedSecret, kem_ct)
        DEK->>DB: 登记封装密文 kem_ct 至 user_log_kem_keys 表
    end
    Server->>Server: 采用 AES-256-GCM (独立随机 IV) 加密日志敏感字段
    Server->>DB: 持久化存储密文日志行

    Note over Admin,DB: 客户端零知识解密阶段 (纯本地计算)
    Admin->>WebUI: 访问日志审计流或统计页面
    WebUI->>Server: 拉取加密日志批次与对应的 hourly kem_ct
    Server-->>WebUI: 返回加密数据包
    WebUI->>Passkey: 发起 WebAuthn 硬件签名授权
    Passkey-->>WebUI: 释放受保护的 ML-KEM-768 用户主私钥
    WebUI->>WebUI: 本地内存执行 ML-KEM-768 解封装: decapsulate(PrivKey, kem_ct)
    WebUI->>WebUI: 还原当前小时对称 DEK
    WebUI->>WebUI: 批量解密 AES-256-GCM 密文并写入本地 OPFS SQLite
    WebUI-->>Admin: 呈现解密明文分析视图
```

### 4. 本地優先 (Local-First OPFS) 增量同步與離線查詢流

```mermaid
sequenceDiagram
    autonumber
    actor User as 用户界面 (React UI)
    participant Bridge as LocalDb 桥接层
    participant Engine as 增量同步引擎 (SyncEngine)
    participant OPFS as 本地 SQLite WASM (OPFS)
    participant Remote as 远程 API (D1 / Turso)

    User->>Bridge: 挂载视图并监听数据变更
    Bridge->>Engine: 触发增量同步检查
    Engine->>OPFS: 读取本地日志最小与最大 ID 水位线 (min_id, max_id)
    OPFS-->>Engine: 返回当前边界水位
    Engine->>Remote: 发送前向增量同步请求 (after_id = max_id)
    Remote-->>Engine: 返回最新增量密文批次
    opt 存在历史时间空隙
        Engine->>Remote: 请求回填缺失时间区间的日志
        Remote-->>Engine: 返回回填密文批次
    end
    Engine->>OPFS: 执行事务批量插入本地 SQLite
    OPFS-->>Engine: 落盘完成确认
    Engine-->>Bridge: 同步完成通知
    Bridge-->>User: 触发状态响应更新
    User->>OPFS: 发起复杂多维聚合查询 (按时间/ISP/国家/拦截原因)
    OPFS-->>User: 本地 Worker 0ms 瞬间返回计算结果
```
