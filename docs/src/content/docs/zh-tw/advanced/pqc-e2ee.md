DNS Worker 為查詢日誌提供了行業領先的**後量子零知識端到端加密（E2EE）**架構，確保即便在未來量子計算機攻擊下，歷史 DNS 訪問記錄在數學上依然保持不可逆性。

## 預設狀態與開啟方式

> [!NOTE]
> **預設停用**：系統為所有新註冊賬戶**預設關閉**端到端加密。在此預設模式下，DNS 查詢日誌以明文直接儲存，具備最優的讀寫吞吐效能、跨裝置即時可讀性以及 0 前端解密開銷。

### 如何啟用 E2EE (按需開啟)

若您追求數學層面的絕對零知識隱私：

1. 進入 **Account & Security**（賬戶與安全）中的 **E2EE (端到端加密)** 卡片。
2. 點選 **通過通行金鑰生成金鑰對**（推薦，支援生物識別秒級解鎖）或 **通過恢復金鑰初始化**。
3. 初始化成功後，所有新入庫的 DNS 日誌將自動在服務端使用 NIST FIPS 203 **P256-MLKEM768** 後量子金鑰加密後再持久化。
4. 您可以隨時在卡片中暫停或重啟 E2EE，歷史金鑰與已加密日誌將被完整保留。

## 核心安全支柱

1. **零知識儲存保證**：
   - DNS Worker 後臺僅持有使用者的公開公鑰用於加密入庫日誌；
   - 服務端資料庫從未儲存解密私鑰，杜絕服務端洩露風險。
2. **NIST FIPS 203 混合格密碼**：
   - 結合經典橢圓曲線與 **P256-MLKEM768**，防範 Shor 量子分解演算法破解。
3. **每小時動態輪換 KEM DEK**：
   - 資料加密金鑰（DEK）每小時自動輪換，收斂金鑰暴露視窗。
   - 封裝密文（`kem_ct`）與輪換生命週期安全記錄於資料庫中：

![Cloudflare D1 後量子 KEM 封裝金鑰表](/DNS-Worker/screenshots/d1-studio-kem.png)

4. **硬體通行金鑰（WebAuthn）防護**：
   - 使用者藉助裝置生物識別（Touch ID、Face ID、Windows Hello 或 YubiKey）解密主私鑰，私鑰解密僅在受信任客戶端瀏覽器內完成。
